# 経費の費目分類

freee 法人標準の勘定科目に、会計の専門家の基準で分類する。

keiri-app の経費（`expenses` タブ）を **freee 会計（法人）の標準勘定科目**に分類する基準と実装。
**安定パフォーマンスの肝＝決定論ルール辞書で大半を確定し、残りだけ AI(Gemini)**。AI 依存を最小化して再現性・速度・コストを安定させる。

## 勘定科目

freee 法人標準の正式名称と完全に一致させる。

旅費交通費 / 通信費 / 消耗品費 / 会議費 / 接待交際費 / 広告宣伝費 / 新聞図書費 / 研修費 / 支払手数料 / 外注費 / 荷造運賃 / 水道光熱費 / 地代家賃 / 修繕費 / 保険料 / 租税公課 / 福利厚生費 / 車両費 / 諸会費 / 雑費 / **要確認**

- すべて freee 法人のデフォルト科目と**正式名称が一致**（保険料・車両費・研修費・外注費 は freee 表記。損害保険料/車両関連費/研修採用費/外注工賃 にしない）。
- **「要確認」だけは freee に無いアプリ独自ラベル**（高額・私的疑い・判断不能の人間レビュー用）。freee 連携前に必ず実科目へ手修正する。
- 定義・該当する代表店/サービス例・税区分は `references/accounting-categories.md` 参照。

## 判断基準

- 打合せ/会議の飲食で 1人 ≤ 1万円 → **会議費**。1人 > 1万円・取引先接待/贈答 → **接待交際費**（2024/4〜 1万円基準）。
- 物品購入 < 10万円 → **消耗品費**。**10万円以上の物品 → 要確認**（固定資産の可能性）。
- クラウド/SaaS/AIツール/通信（AWS・Google・Slack・ChatGPT 等）→ **通信費**。決済・取引手数料 → **支払手数料**。
- 書籍・新聞・技術コンテンツ → **新聞図書費**。講座・セミナー → **研修費**。
- 電車/バス/タクシー/航空 → **旅費交通費**。ガソリン/ETC/駐車 → **車両費**。配送 → **荷造運賃**。
- 電気/ガス/水道 → 水道光熱費。保険 → 保険料。会費 → 諸会費。
- **「雑費」に逃げない**（雑費が多いと税務調査の的・融資評価低下）。事業性不明・私的疑い・高額で判断不能は **要確認**。雑費は経費総額の 5〜10% 以内が目安。

## 実装

- `scripts/classify.mjs` … 基準の実装。`CATEGORIES`（上記科目）、`RULES`（店名正規表現→科目の決定論辞書、半角カナ対応）、`CLASSIFY_GUIDE`（AI 用基準）、`classify(items, geminiKey)`（ルール→金額ルール(10万円)→AI補完→要確認フォールバック）。
- **自己学習辞書（最優先・自動）**：`merchant_rules` シート＝利用先(正規化キー)→費目の対応表。分類の優先順は **学習辞書 → RULES → 金額(10万円) → Gemini → 要確認**。アプリ一覧で費目を変更すると、その利用先が**自動で学習辞書に記憶**され（`updateExpenseCategory` → `merchantRules.upsert`）、次回から同じ店は AI を介さず即確定。表記ゆれは `normalizeMerchant`（`classify.mjs` と `src/domain/reports.ts` で一致）で名寄せ（メール表記 `ｻﾝﾌﾟﾙ…` と CSV表記 `ＶＩＳＡ国内利用　VS ｻﾝﾌﾟﾙ…` が同一キー）。初期投入は `node scripts/seed-merchant-rules.mjs`（既存 expenses の最頻確定費目から生成）。GAS取込・各取込/再分類スクリプトもこの辞書を読んで適用する。
- **精度の育て方**：(1) 普段は一覧で費目を直すだけで自動学習される。(2) 業種横断のパターン（全ガソリン→車両費等）は `scripts/classify.mjs` の `RULES` に `[/店名正規表現/i, "科目"]` を足す。`SKILL.md` の科目と `src/domain/expense.ts` の `EXPENSE_CATEGORIES`・`classify.mjs` の `CATEGORIES` は3つとも一致させる。

## 取込経路

- **楽天カード = メール自動取込が正**（`scripts/gas/` の GAS が確定版「カード利用のお知らせ」を1時間ごとに取込。source=`楽天メール`）。**同じ期間を CSV (`import-rakuten.mjs`) でも取り込むと二重計上**になる（メールとCSVで店名表記が違い `date|merchant|amount` 重複判定をすり抜ける）。楽天カードは原則 CSV 取込しない。
- **PayPay = CSV取込**（`scripts/import-paypay.mjs`、支払いのみ、source=`PayPay`）。メール経路は無し。
- **経費の事業/私用区分は廃止**（一人会社で一つの財布として扱う。区分なし）。
- GASはGeminiキー未設定運用のため新規メール分は費目`要確認`で入る → `reclassify-expenses.mjs` で AI 精緻化（または一覧で手修正）。

## 運用コマンド

ローカルで、リポジトリのルートから実行する。

- 取込：`node scripts/import-paypay.mjs <csv>`（PayPay）。楽天カードはメール自動（CSVは原則使わない）。
- 全件再分類：`node scripts/reclassify-expenses.mjs`（基準変更・RULES追加後／メール取込の要確認を埋める時に流す。手修正も上書きする点に注意）。
- 集計確認：`node scripts/check-expenses.mjs`（件数・費目別合計）。

## freee 連携の注意

- freee は科目名の**完全一致**が必要（前後スペースも不可）。上記正式名称を使う。CSVインポートで不一致だと重複科目が新規作成される。API は `account_item_id`（数値）指定が正確。
- **「要確認」は連携対象にしない**（人間が実科目へ確定してから）。
