# keiri-app

## これは何か

- 請求書、経費、会計帳簿、決算資料を管理するアプリです。
- データは、あなたの Google ドライブにあるスプレッドシートにだけ保存されます。
- 複数人で使えます。ログイン、役割、2 段階認証、操作の記録（監査ログ）があります。
- 無料で使えて、ライセンスは MIT です。

## できること

- 請求書、見積書、納品書、発注書、領収書を作る。番号は自動でつく。PDF にもできる。
- 経費を記録する。手で入力する、レシートを撮影する、カード明細の CSV を取り込む、のどれでもできる。
- 銀行の入出金の CSV を取り込み、請求書の入金と照らし合わせる。
- 損益計算書、貸借対照表、仕訳帳、総勘定元帳を見る。
- 決算の集計と、freee に取り込める CSV を出す。
- 複数の会社の帳簿を、1 つのアプリで切り替えて使う。
- API で、外部のプログラムから書類を作る。
- 管理者が招待リンクを作って、メンバーを増やす。役割は、管理者とメンバーの 2 つ。
- ログインに、2 段階認証（認証アプリの 6 桁のコード）を使う。全員に必須にもできる。
- だれが、いつ、何をしたかを、監査ログで見る。

## 使っているもの

| 名前                    | 役割                                           |
| ----------------------- | ---------------------------------------------- |
| Google スプレッドシート | データの保存先。あなたの Google ドライブに置く |
| Google Apps Script      | スプレッドシートとアプリをつなぐ               |
| Cloudflare Workers      | アプリを動かす場所                             |
| Next.js と vinext       | アプリの作り                                   |
| Node.js と npm          | インストールと、アプリの組み立て               |
| Git                     | アプリのファイルの取得                         |

- マスターのスプレッドシートをコピーすると、データの表、帳票の書式、Apps Script が、まとめて自分のものになります。
- アプリに設定する秘密の値は、接続コード 1 つだけです。
- Google Cloud のプロジェクトも、サービスアカウントの鍵も、要りません。

## はじめる前に用意するもの

- Google アカウント
- Cloudflare のアカウント（無料プランで動きます）
- Node.js 22.18 以上
- Git

## 自分で入れる

1 から 5 まで、順番に進めます。所要時間は、30 分ほどです。

### 1. 帳簿のスプレッドシートを自分のドライブにコピーする

1. [マスターのスプレッドシート](https://docs.google.com/spreadsheets/d/1FazkgSK-4GCK8LMRZUqNFKnRQyyUjp06qBMLXIcH64g/copy) を開く。
2. 「コピーを作成」を押す。
3. 自分の Google ドライブに、コピーができる。
4. 名前は、好きなものに変えてよい。

### 2. スプレッドシートをウェブアプリとして公開する

1. コピーしたスプレッドシートで、メニューの「拡張機能」から「Apps Script」を開く。
2. 右上の「デプロイ」から「新しいデプロイ」を選ぶ。
3. 「種類の選択」の歯車から「ウェブアプリ」を選ぶ。
4. 「次のユーザーとして実行」を「自分」にする。
5. 「アクセスできるユーザー」を「全員」にする。
6. 「デプロイ」を押す。
7. 「アクセスを承認」を押し、自分の Google アカウントを選ぶ。
8. 「このアプリは Google で確認されていません」と出たら、「詳細」から「keiri-app（安全ではないページ）に移動」を押す。
9. 求められた権限を「許可」する。
10. 表示された「ウェブアプリ」の URL をコピーする。

- 手順 8 の画面は、自分のスクリプトを初めて動かすときに出ます。
- 動くのは、自分のドライブにコピーされたスクリプトだけです。
- 「全員」にしても、接続コードを知らない人は、データを読めません。

### 3. 接続コードを作る

1. スプレッドシートに戻り、ページを読み込み直す。
2. メニューに増えた「keiri-app」から「接続コードを発行」を選ぶ。
3. 手順 2 でコピーした URL を貼り付けて、「接続コードを発行」を押す。
4. 表示された接続コードをコピーする。

- 接続コードを知っている人は、このスプレッドシートを読み書きできます。
- 人に見せたり、公開の場所に貼ったりしないでください。

### 4. アプリをインターネットに公開する

1. アプリのファイルを取得する。

   ```bash
   git clone https://github.com/strickland-inc/keiri-app.git
   ```

2. フォルダに入り、必要なものを入れる。

   ```bash
   cd keiri-app && npm ci
   ```

3. 設定ファイルのひな形をコピーする。

   ```bash
   cp .env.example .env.local
   ```

4. `.env.local` を開き、`KEIRI_CONNECTION=""` の `""` の中に、接続コードを貼り付ける。
5. Cloudflare にログインする。

   ```bash
   npx cf auth login
   ```

6. 公開する。

   ```bash
   npm run deploy
   ```

7. 最後に表示された `https://keiri-app.<あなたのサブドメイン>.workers.dev` を開く。

### 5. 最初の管理者を作る

1. アプリを開くと、「最初の管理者を作る」の画面が出る。
2. 接続コードを貼り付ける。
3. ログイン ID、表示名、12 文字以上のパスワードを決める。
4. 「管理者を作って始める」を押す。
5. メニューの「会社」で、自分の会社の名前、住所、振込先を登録する。
6. メニューの「取引先」で、請求先を登録する。
7. メニューの「請求・入金」の「請求書」から、最初の請求書を作る。

## メンバーを増やす

メールは送りません。招待や再設定のリンクは、管理者が自分で相手に渡します。

### 招待リンクを送る

1. 管理者が、メニューの「ユーザー管理」を開く。
2. 役割（管理者かメンバー）と、だれ向けかのメモを決めて、「招待リンクを作る」を押す。
3. 表示されたリンクをコピーして、相手に渡す。
4. 相手がリンクを開き、ログイン ID、表示名、パスワードを決める。

- リンクは、作った直後に 1 度しか表示されません。閉じてしまったら、取り消して作り直します。
- リンクは 7 日で切れます。1 度使うと、使えなくなります。
- 使えないリンクは、理由に関係なく、同じ文言で断られます。
- まだ使われていない招待は、一覧から取り消せます。
- 渡すときは、チャットなど、相手だけが見られる場所を使ってください。

### 管理者とメンバーのちがい

| 役割     | できること                                                     |
| -------- | -------------------------------------------------------------- |
| 管理者   | 帳簿の操作に加えて、ユーザー管理、監査ログ、API トークンの発行 |
| メンバー | 帳簿の操作と、自分のアカウントの管理                           |

- 有効な管理者が 1 人だけのときは、その人の降格、無効化、削除はできません。
- 自分自身の無効化と削除もできません。
- 管理者を無効化、削除、降格すると、その人が作った未使用の招待リンクと再設定リンクは、取り消されます。

### 使えなくする、削除する

- 無効化すると、その人はすぐにログアウトになり、ログインできなくなります。あとで元に戻せます。
- 削除すると、そのユーザーは消えます。
- 無効化や削除をした人の API トークンは、自動では消えません。「API トークン」の画面で、別に取り消してください。

### パスワードを忘れた人

1. 管理者が、ユーザー管理でその人の「再設定リンクを作る」を押す。
2. リンクを本人に渡す。
3. 本人がリンクを開き、新しいパスワードを決める。

- 再設定リンクは、24 時間で切れます。1 度しか使えません。
- 再設定すると、その人が開いている端末は、すべてログアウトになります。2 段階認証の設定は、そのまま残ります。
- 管理者が、ほかの人のパスワードを決めることも、見ることもできません。

### 2 段階認証を使う

1. 「アカウント」を開く。
2. パスワードを入れて「設定を始める」を押し、QR コードを認証アプリで読み取る。読み取れないときは、表示された文字列を手で入れる。
3. 認証アプリに出た 6 桁のコードを入れて、有効にする。
4. 表示された回復コード 10 個を、安全な場所に控える。

- 回復コードは、有効にした直後に 1 度しか表示されません。1 個につき 1 回だけ使えます。
- 認証アプリを失くしたときは、ログインの 2 段階目で、回復コードを入れます。
- 回復コードは、「アカウント」から作り直せます。古いものは、すべて使えなくなります。
- 設定を始めるときと、解除するときは、パスワードをもう一度入れます。
- 管理者は、ほかの人の 2 段階認証をリセットできます。端末を失くし、回復コードもない人のために使います。

### 全員に 2 段階認証を必須にする

1. 管理者が、自分の 2 段階認証を設定する。
2. 「セキュリティ」の画面で、必須にする。

- 設定済みの管理者だけが、切り替えられます。管理者自身が入れなくなるのを防ぐためです。
- 必須にすると、未設定の人は、次にログインするときに、その場で設定します。
- 必須の間は、本人は 2 段階認証を解除できません。

### だれが何をしたか見る

- 管理者が、「監査ログ」の画面で見ます。新しい順に、最大 500 件を出します。
- 操作の種類と、人で絞り込めます。
- 次のことが残ります。
  - ログイン（成功、失敗、ロック）
  - メンバーの追加と変更
  - パスワードと 2 段階認証の変更
  - 書類や経費などの作成、更新、削除
- ログインの失敗は、15 分ごとに、最初の 1 回だけ残ります。
- パスワード、トークン、接続コード、回復コードは、記録しません。
- 監査ログのタブは、追記だけです。ただし、スプレッドシートを編集できる人は、書き換えられます。証拠として使うときは、スプレッドシートの共有を絞ってください。

## 管理者がログインできなくなったとき

全員がログインできなくなったときは、`/recover` の画面から直します。

1. アプリの `/recover` を開く。
2. 接続コード、管理者のログイン ID、新しいパスワードを入れる。
3. 新しいパスワードで、ログインする。

- 接続コードが合い、そのログイン ID が管理者のものであるときだけ、通ります。
- その管理者のパスワードが入れ替わります。同時に、次のことが起きます。
  - 2 段階認証が解除される
  - ロックが解ける
  - 無効になっていれば、有効に戻る
  - 開いている端末が、ログアウトになる
- 失敗したときの文言は、1 種類だけです。ID があるかどうかは、分かりません。
- 実行すると、監査ログに残ります。
- 接続コードを知る人は、だれでもできます。接続コードは、人に見せないでください。

## 安全に使うコツ

法人で使う担当者は、先にこの節を読んでください。

- **スプレッドシートを共有した人は、会計データを全部読めます。** Google ドライブで共有された人は、アプリを通さずに、すべてのタブを開けます。
  - タブの中には、パスワードを変換した値（ハッシュ）も入っています。弱いパスワードは、ここから割り出されることがあります。
  - だから、スプレッドシートは共有しないでください。共有するときは、2 段階認証を必須にしてください。
- **接続コードを知る人は、スプレッドシートを読み書きできます。** 接続コードは、`.env.local` と Cloudflare にだけ置き、チャットやメールに貼らないでください。
- **無料プランでは、パスワードの変換の回数を 20,000 回に抑えています。** Cloudflare の無料プランは、1 回の処理に使える CPU 時間が 10 ミリ秒だからです。有料プランでは、環境変数 `KEIRI_PASSWORD_ITERATIONS` で、100,000 回まで上げられます。
- **ログインに失敗すると、ロックがかかります。** 回数は、次のとおりです。正しく入れた試行も、回数に入ります。
  - 同じ ID に、同じ接続元から、15 分に 10 回を超えて試すと、ロックされる。
  - ID ごとの合計が、1 時間に 50 回を超えても、ロックされる。
  - 2 段階認証のコードは、ユーザーごとに 15 分に 5 回まで。
  - パスワードの再入力（パスワードの変更、2 段階認証の設定など）は、ユーザーごとに 15 分に 10 回まで。
- **接続コードを作り直すと、全員がログアウトになります。** 2 段階認証と回復コードも、全員が設定し直しになります。保管してある値が、新しい接続コードでは読めなくなるためです。
  - 2 段階認証を必須にしているときは、設定し直すまで、その人はログインできません。
  - パスワードは、そのまま使えます。
- **このアプリで守れないことがあります。** Cloudflare の管理者と、`.env.local` を持つ人は、接続コードを持っているのと同じです。メールで届くリンクの保護や、端末のウイルスの対策は、このアプリの範囲外です。

脆弱性を見つけたときの報告先は、[SECURITY.md](SECURITY.md) にあります。

## 自分のパソコンで試す

1. アプリのファイルを取得して、`npm ci` を実行する。
2. `npm run dev` を実行する。
3. `http://localhost:3000` を開く。

- 接続コードを設定していないときは、デモのデータで動きます。
- デモでは、ログインは要りません。
- デモのデータは保存されず、止めると消えます。
- デモでは、PDF は作れません。

ログインの流れ（最初の管理者、招待、2 段階認証）を試すときは、次のように起動します。

```bash
KEIRI_DEMO_AUTH=1 npm run dev
```

- 最初に `/setup` が開きます。接続コードの欄には、`demo` と入れます。
- 接続コードを設定していないときの、手元の起動だけで使えます。
- 本番では、この設定は無視されます。
- データはメモリに置くので、止めると消えます。

## 細かい設定

- `GEMINI_API_KEY` を入れると、帳票のたたき台、レシートの読み取り、収支の改善提案が使えます。
- `TYPESAFE_API_KEY` を入れると、銀行明細の勘定科目を自動で決めます。
- どちらも、`.env.local` に入れてから `npm run deploy` をやり直すと、反映されます。
- 入れなくても、ほかの機能は、そのまま使えます。
- `KEIRI_PASSWORD_ITERATIONS` に 20000 から 100000 の整数を入れると、パスワードの変換の回数が変わります。初期値は 20000 です。Cloudflare の有料プランでだけ、上げてください。範囲外の値は、初期値に戻ります。
- 変えても、今のパスワードは、そのまま使えます。次にパスワードを変えたときから、新しい回数になります。

## スプレッドシートの中身

- `書式_請求書` などのタブは、帳票の書式です。
  - 色、罫線、文字の大きさは、好きに変えられます。
  - セルの位置は、変えないでください。
- `documents`、`parties`、`expenses` などのタブは、アプリが読み書きする表です。
  - 1 行目の見出しと、列の並びは、変えないでください。
- 書類を作ると、`請求書_0001_取引先名` のようなタブが増えます。
  - PDF は、このタブを Google が書き出したものです。
  - 書類を編集するとタブは作り直され、書類を削除するとタブも消えます。
- `user_profiles`、`user_security`、`user_access`、`session_versions`、`auth_counters`、`invites`、`audit_log` は、ログインとメンバー管理のタブです。アプリが増やします。手で触らないでください。

## API

- アプリの「API トークン」の画面で、トークンを発行します。
- トークンは、`Authorization: Bearer <トークン>` のヘッダーに付けます。
- トークンは、発行したときにしか表示されません。
- 要らなくなったトークンは、同じ画面で削除します。

| メソッドとパス                     | 内容                                                         |
| ---------------------------------- | ------------------------------------------------------------ |
| `GET /api/v1/documents`            | 取引先、会社、書類の一覧を返す。                             |
| `POST /api/v1/documents`           | 書類を作る。`?dryRun=1` を付けると、保存せずに内容だけ返す。 |
| `POST /api/v1/documents/<id>/void` | 書類を無効にする。                                           |
| `PATCH /api/v1/issuers/<id>`       | 会社の住所、連絡先、振込先を変える。                         |

- 同じ会社、種類、取引先、発行日、件名の書類は、二重に作りません。

## 新しいバージョンにする

アプリを新しくするときは、次の 2 つを実行します。

```bash
git pull
npm ci && npm run deploy
```

スプレッドシート側の Apps Script も新しくするときは、次のとおりです。

1. `apps-script/` の 3 つのファイル（`Code.gs`、`Dialog.html`、`appsscript.json`）の中身を、Apps Script の同じ名前のファイルに貼り付けて保存する。
2. 「デプロイ」の「デプロイを管理」から、鉛筆のアイコンを押す。
3. バージョンを「新バージョン」にして、デプロイする。

- `appsscript.json` は、Apps Script の「プロジェクトの設定」で「「appsscript.json」マニフェスト ファイルをエディタで表示する」をオンにすると、表示されます。
- この方法なら、ウェブアプリの URL と接続コードは変わりません。

メンバー管理の機能が入った更新では、次のとおりです。

- Apps Script の貼り直しと、再デプロイは要りません。`git pull` のあと `npm ci` と `npm run deploy` だけで済みます。
- 新しいタブ（`user_profiles`、`user_security`、`user_access`、`session_versions`、`auth_counters`、`invites`、`audit_log`）は、アプリが自動で増やします。
- 今のユーザーは、そのままログインできます。パスワードも、ログイン中の端末も、変わりません。

## こまったとき

| 出ること                                                    | 原因と直し方                                                                                                               |
| ----------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 「サーバーの設定が足りないため、利用できません」            | `KEIRI_CONNECTION` が入っていないか、形が違う。                                                                            |
| 「スプレッドシートから想定外の応答が返りました」            | ウェブアプリの「アクセスできるユーザー」が「全員」になっていない。                                                         |
| 「接続コードが違います」                                    | 接続コードを作り直したあと、アプリ側を入れ替えていない。                                                                   |
| 「ID またはパスワードが違うか、一時的にロックされています」 | パスワードの間違いか、失敗が続いたロック。15 分あけて試す。急ぐときは、管理者に再設定リンクを頼む。                        |
| 招待リンクが「無効」                                        | 7 日の期限切れか、使用済み。管理者に作り直してもらう。                                                                     |
| 503 がたびたび出る                                          | Cloudflare の無料プランの上限（1 回の処理につき CPU 10 ミリ秒）を超えている。有料プラン（月 5 米ドルから）にすると収まる。 |

- パスワードを忘れたときは、管理者に再設定リンクを頼みます。
- 認証アプリを失くしたときは、回復コードでログインします。回復コードもないときは、管理者に 2 段階認証のリセットを頼みます。
- 2 段階認証のコードを間違え続けたときも、15 分あけます。
- 管理者がログインできないときは、「管理者がログインできなくなったとき」の手順で直します。
- 接続コードを他の人に知られたときは、メニューの「接続コードを作り直す」で新しくし、`.env.local` を直して `npm run deploy` をやり直します。
  - 作り直すと、全員がログアウトになり、2 段階認証と回復コードは設定し直しになります。パスワードは、そのまま使えます。

## 開発する人へ

| コマンド               | 内容                                |
| ---------------------- | ----------------------------------- |
| `npm run dev`          | 手元で起動する。                    |
| `npm test`             | テストを実行する。                  |
| `npm run lint`         | 書き方を検査する。                  |
| `npm run build:vinext` | Cloudflare Workers 用に組み立てる。 |
| `npm run deploy`       | Cloudflare Workers に公開する。     |
| `npm run icons`        | アイコン用のフォントを作り直す。    |

- `apps-script/` は、スプレッドシート側のスクリプトです。
- `src/repositories/` は、保存先を扱う層です。
- `src/domain/` は、採番、税の計算、仕訳などのきまりです。
- `src/lib/documents/sheet.ts` は、帳票のどのセルに何を書くかを決めます。
- 画面のきまりは、[DESIGN.md](DESIGN.md) にあります。
